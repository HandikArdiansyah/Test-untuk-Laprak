4. Kenapa Informasi Memudar?

Ini kunci untuk memahami mengapa ReLU penting.

Apa yang dilakukan Sigmoid?

Sigmoid memaksa semua angka masuk ke rentang 0–1, dengan bentuk kurva S.

  • Input sangat negatif → output mendekati 0
  • Input sangat positif → output mendekati 1
  • Input di tengah → output sekitar 0.5

Masalahnya: begitu output mendekati 0 atau 1, perubahan input tidak lagi mengubah output. Kurvanya mendatar.

Apa yang dilakukan ReLU?

ReLU(x) = max(0, x). Tidak ada "pembungkusan".

  • Input negatif → output 0 (mati)
  • Input positif → output sama dengan input (utuh)

Informasi di x > 0 lewat apa adanya. Tidak ada pemampatan.

Tabel: Seberapa Banyak Informasi yang Lolos?

ActivationGradient maksimumInformasi yang lolosCocok untuk
Sigmoid 0.25 ~25% — banyak hilang Output biner
Tanh 1.0 (tapi cepat menipis) ~50% — lebih baik, tetap hilang Jarang
ReLU 1 (untuk x > 0) 100% — utuh Hidden layer
Angka konkret — perhatikan betapa kecilnya perubahan:
Input x = 3.0 → σ(3.0) = 0.953
Input x = 4.0 → σ(4.0) = 0.982   (beda input 1.0, beda output hanya 0.03)

Bandingkan dengan ReLU:
Input x = 3.0 → ReLU(3.0) = 3.0
Input x = 4.0 → ReLU(4.0) = 4.0   (beda input 1.0, beda output 1.0 — utuh!)
Kesimpulan bagian ini:
Sigmoid di hidden layer membuat informasi menipis setiap kali melewati satu layer. Menambah layer Sigmoid justru memperparah pemudaran ini. Inilah yang disebut vanishing information (informasi yang menghilang).

Analogi Sederhana

Sigmoid saja = Corong sempit

Semua air dipaksa masuk melalui corong sempit. Tekanan dan kecepatan air berubah — informasi tentang "seberapa deras air masuk" hilang.

ReLU = Keran air

Kalau alirannya positif, air lewat apa adanya (tidak dipadatkan). Kalau negatif, keran ditutup. Informasi tentang "seberapa deras" tetap terjaga.

Penting: ReLU tidak menggantikan Sigmoid di output layer. Sigmoid tetap dipakai di ujung network (untuk mengubah hasil menjadi probabilitas 0–1). Yang berubah adalah hidden layer: dari Sigmoid → ReLU.

Kalimat kunci yang harus diingat mahasiswa:
"Single neuron dengan Sigmoid itu cukup untuk masalah sederhana. Tapi begitu kita butuh network yang lebih dalam untuk pola yang lebih rumit, kita butuh ReLU di hidden layer. Bukan karena ReLU lebih modern, tapi karena ReLU tidak memampatkan informasi seperti Sigmoid."
Aturan praktis yang akan dipakai seterusnya:
  • Hidden layer → ReLU
  • Output biner → Sigmoid
  • Output multiclass → Softmax (akan dibahas nanti)
  • Output regresi → Linear (tanpa activation)

8. Sekarang: Bagaimana Network Belajar?

Kita sudah tahu susunan network yang baik. Tapi dari mana weight yang tepat berasal?

Analogi melempar panah:
Bayangkan Anda melempar panah ke papan target. Lemparan pertama meleset. Anda lihat seberapa jauh dari pusat, lalu koreksi lemparan berikutnya. Network belajar dengan cara yang sama.

8.1 Loss Function — "Seberapa Salah Prediksi Saya?"

Loss adalah satu angka yang merangkum: seberapa jauh prediksi dari jawaban benar.

Untuk klasifikasi biner, kita pakai Binary Cross-Entropy (BCE):

L = −[ y · log(ŷ) + (1 − y) · log(1 − ŷ) ]
Bacaan visual rumus ini:
  • Jika target y = 1 dan prediksi ŷ = 0.99 → loss ≈ 0.01 (hampir sempurna)
  • Jika target y = 1 dan prediksi ŷ = 0.10 → loss ≈ 2.30 (sangat salah)
  • Loss menghukum prediksi yang percaya diri tapi salah jauh lebih berat

8.2 Gradient Descent — "Ke Arah Mana Bergerak?"

Bayangkan loss sebagai lembah. Kita ingin sampai ke dasar (loss = 0).

w ← w − η · ∂L/∂w

η (eta) = learning rate — seberapa besar langkah yang diambil

η terlalu kecil

Langkah mungil. Konvergen, tapi sangat lambat. Butuh ribuan epoch.

η pas

Turun mulus dan cepat. Ini yang kita inginkan.

η terlalu besar

Melompati lembah, bahkan mental ke atas. Loss tidak turun.

8.3 Backpropagation — "Weight Mana yang Paling Bersalah?"

Loss memberi tahu seberapa salah. Backpropagation mencari tahu weight mana yang harus diubah: error mengalir mundur dari output ke input.

Panah besar = gradient besar = weight ini paling berpengaruh terhadap loss.

Kaitkan dengan ReLU yang tadi dibahas!
Saat error mengalir mundur melewati hidden layer:
  • Jika hidden pakai Sigmoid → gradient dikalikan ≤ 0.25 tiap layer → error menipis → layer awal nyaris tidak belajar.
  • Jika hidden pakai ReLU → gradient dikalikan 1 (untuk x > 0) → error mengalir utuh → semua layer ikut belajar.

9. Bukti Kuantitatif

Kalau teori di atas benar, maka saat kita training network dengan data yang sama, hanya dengan mengganti activation function, hasilnya harus berbeda.

Yang akan kita lihat di praktik nanti:
Dengan data yang sama, arsitektur sama, jumlah neuron sama, optimizer sama — hanya activation di hidden layer yang berbeda:
  • Tanpa activation → loss mandek (seperti tebak)
  • Sigmoid → loss turun lambat
  • ReLU → loss turun cepat dan dalam

10. Praktik PyTorch — 3 Eksperimen

Sekarang kita buktikan teorinya dengan kode nyata. Studi kasus: pabrik ban, klasifikasi Baik / Perlu Perbaikan.

Dataset & Persiapan

import torch import torch.nn as nn import matplotlib.pyplot as plt torch.manual_seed(42) # ====== Dataset sintetis: 200 ban ====== # Fitur: suhu, tekanan, waktu curing, rasio karet n = 200 X = torch.rand(n, 4) X[:, 0] = X[:, 0] * 40 + 140 # suhu 140-180 X[:, 1] = X[:, 1] * 10 + 15 # tekanan 15-25 X[:, 2] = X[:, 2] * 7 + 8 # waktu 8-15 X[:, 3] = X[:, 3] * 0.4 + 0.4 # rasio 0.4-0.8 # Aturan non-linear: ban baik jika suhu di rentang "ideal" (150-165) # dan tekanan cukup. suhu_ideal = ((X[:, 0] > 150) & (X[:, 0] < 165)).float() tekanan_ok = (X[:, 1] > 19).float() y = ((suhu_ideal * 0.7 + tekanan_ok * 0.3) > 0.6).float().unsqueeze(1) # Normalisasi fitur (penting untuk training stabil) X = (X - X.mean(0)) / X.std(0)

Arsitektur & Fungsi Training

def build_model(hidden_activation): return nn.Sequential( nn.Linear(4, 8), hidden_activation, nn.Linear(8, 8), hidden_activation, nn.Linear(8, 1), nn.Sigmoid() # output tetap Sigmoid ) def train(hidden_activation, epochs=300, lr=0.01): torch.manual_seed(42) model = build_model(hidden_activation) loss_fn = nn.BCELoss() optimizer = torch.optim.Adam(model.parameters(), lr=lr) losses = [] for epoch in range(epochs): y_pred = model(X) loss = loss_fn(y_pred, y) optimizer.zero_grad() loss.backward() # <-- backpropagation optimizer.step() # <-- update weight losses.append(loss.item()) return losses

Bandingkan 3 Konfigurasi

configs = { "Tanpa Activation": nn.Identity(), "Sigmoid": nn.Sigmoid(), "ReLU": nn.ReLU(), } results = {} for name, act in configs.items(): losses = train(act) results[name] = losses print(f"{name:20s} | Loss akhir: {losses[-1]:.4f}")

Visualisasi Hasil

plt.figure(figsize=(10, 5)) for name, losses in results.items(): plt.plot(losses, label=name, linewidth=2) plt.xlabel("Epoch") plt.ylabel("Loss") plt.title("Perbandingan Activation Function di Hidden Layer") plt.legend() plt.grid(True) plt.show()
Pesan utama eksperimen:
Data sama, arsitektur sama, jumlah neuron sama, optimizer sama. Yang berbeda hanya activation function di hidden layer. ReLU membuat loss turun jauh lebih cepat dan lebih dalam. Inilah buktinya secara kuantitatif.

Kalimat penutup untuk mahasiswa

"Single neuron dengan Sigmoid belajar satu transformasi sederhana. Kalau kita menumpuk Sigmoid, network tidak menjadi lebih pintar — informasinya justru memudar. Dengan menambahkan ReLU di hidden layer, informasi tetap utuh, dan network benar-benar bisa belajar pola yang lebih kompleks. Itulah mengapa hidden layer memakai ReLU, dan output memakai Sigmoid."
